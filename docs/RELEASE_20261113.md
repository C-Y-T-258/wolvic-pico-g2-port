# Pico G2 community build: 2026-11-13

Status: published as a community prerelease on 2026-11-18 (Asia/Shanghai).
[Release, downloads and checksums](https://github.com/C-Y-T-258/wolvic-pico-g2-port/releases/tag/picog2-1.6.2-20261113).
Build 0052 remains the published fallback. This build closes the current development round; it does not
claim that every originally investigated player or site is fully supported.

## Changes since 0052

- General browser extension menu and native projection handoff, with media
  identity and lifecycle checks.
- Per-page Quest/Oculus UA fallback for site VR entry.
- Shared MGP canvas/control compatibility extended to YouPorn.
- Stable hover behavior in the shared native choice widget; the user accepted
  the hover, selection and common-control regression checks.
- Codec discovery and switching organized by player/protocol API, including
  explicit HTML sources, Video.js/VHS, hls.js, dash.js, Shaka, MGP, Delight and
  reusable xPlayer source controllers.
- Candidate grouping distinguishes codec families from resolution choices.
  The source menu requires at least two confirmed playable codec families for
  the same media. Unknown, single-codec or conflicting evidence stays hidden.
- Switch operations preserve state, verify results and handle recovery and
  newer user intent. An unconfirmed switch is reported as such.
- Release label `Wolvic Pico G2` and fixed version metadata. The release
  candidate retains the tested package ID for in-place upgrades.

The player list describes implemented paths, not a list of universally
verified websites. Resolution selection and ABR stay with the site player.
The extension does not take over Bilibili's quality controls.

## Verification boundary

| Path | Evidence | Limit |
| --- | --- | --- |
| Video.js/VHS, Eporner | Natural same-video H.264/AV1 switching in both directions on the final functional baseline | One earlier manifest timeout remains recorded; no universal success or speed claim |
| xPlayer, xHamster | Historical natural dual-codec and quality-mode tests | Not rerun in the final APK; not every video has two codecs |
| HTML sources, hls.js, dash.js | Controlled device player tests, including state and failure cases | Not proof of natural dual-codec support on arbitrary sites |
| Shaka | Controlled device switching and interruption tests | Manual reverse completion, non-default audio and VR combinations incomplete |
| MGP | Natural player binding; controlled original-player switching and recovery | Natural Pornhub/YouPorn dual codecs not demonstrated; resolution mapping incomplete |
| Delight | Natural source discovery and controlled switching | Natural HEVC rejected by device capability; full natural DASH/VR combinations incomplete |
| Bilibili | Site playback/settings observed, no extension takeover | Same-video quality change was not conclusively captured in the last round |
| Ordinary pages, VR/projection | Historical user regression acceptance | No complete final-round matrix of every new adapter with VR/projection |

The extension test suite has 435 passing tests. Controlled tests, historical
acceptance, natural website tests and tests on the newly labelled release
candidate are different evidence levels.

The release candidate changes only the app label and version metadata relative
to the final tested functional baseline. Static APK/source comparisons are
recorded in [the release audit](RELEASE_AUDIT_20261113.md). It has not undergone
a separate headset installation or device acceptance pass.
