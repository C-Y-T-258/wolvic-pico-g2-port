01 / 适配成果

为这款旧头显做了什么

从原生显示、视频交接到网站控件，围绕 Pico G2 的实际使用路径做适配。项目独立于 Wolvic 和 PICO 官方。

01

原生显示与 WebXR

恢复 legacy PicoVR 后端，接入 GeckoView 128，保留 G2 的头部追踪和手柄输入。已有普通网页、视频纹理与沉浸 WebXR 的历史实机记录。

02

视频投影与网页交接

原生 2D、180°、360° 和立体投影，修复早期画面裁切与投影切换白屏。后续候选加入通用视频交接、单页 Quest UA 和共享播放器控件修复。

03

有证据的编码选择

新候选按播放器和协议识别同内容编码，区分编码与清晰度。至少两种编码确认可播放时才显示来源；切换验证、状态保护与失败恢复同时纳入。

03 / 证据与边界

验证到了哪里

下面区分已发布版本、后续候选与受控测试。播放器适配代码存在，不等于所有网站都可切换编码。

路线已有证据边界
PicoVR / WebXR0052 有头显播放、追踪、控制输入与纹理验收记录。仅 Pico G2 系列范围；不是当前 OpenXR 构建。
视频交接与投影Hamezo 等路径有历史原生交接与用户回归；后续候选保留实现。网页全屏、原生投影与网站 VR 分别处理；不承诺所有特殊投影模型。
Video.js / VHSEporner 自然网页 H.264 / AV1 双向切换。有一次清单超时记录；不能外推成所有视频均成功或播放性能提升。
xPlayerxHamster 历史自然双编码与质量模式验证。最终 APK 未逐项重跑；视频本身需提供双编码。
HTML / hls.js / dash.js受控设备播放器、状态和失败恢复测试。不等于任意自然网站双编码已验证。
Shaka / MGP / Delight有受控切换与自然页面绑定、发现等不同层次证据。真实双编码、音轨、质量映射及 VR 组合仍各有缺口。
B站 / 普通网页保持站内控制；已有普通使用回归反馈。最终一轮未完成所有质量与 VR 组合验收。

04 / 安装

安装到 Pico G2

使用头显系统安装器，或从电脑通过 ADB 安装。下载后先核对 SHA256。

  1. 下载并核对 APK

    在头显浏览器下载，或从电脑传到头显的 Download 目录。

  2. 打开系统安装器

    按系统提示允许安装来源，也可使用 ADB 命令从电脑安装。

  3. 启动并测试普通网页

    0052 在应用列表显示为 Wolvic Pico G2 测试版。先确认普通网页和视频，再尝试网站沉浸入口。

adb devices
adb install -r .\Wolvic-1.6.2-gecko128-picog2-arm64-release-0052-production-signed.apk

下载前常见问题

这是 Pico G2 的 Firefox Reality 替代浏览器吗？

可以作为一个社区替代方案。它使用 Wolvic 1.6.2 与 GeckoView 128，为旧 Pico G2 提供较新的网页引擎，但不保证每个现代网站或流媒体服务兼容。

Pico 4、Neo、G3 或 Quest 能装吗？

这个移植针对 Pico G2 / G2 4K 系列。实际测试设备为 Android 8.1 的 G2，只有 arm64 构建。其他设备未验证，新头显应优先使用官方适配。

为什么有时没有媒体来源菜单？

来源选择是新候选功能，0052 没有完整实现。候选只在同一视频至少两种真实、可播放编码确认后显示。单编码、只有分辨率差异、身份不明或设备不支持时隐藏。

能保证 H.264 或 AV1 播放更流畅吗？

不能。网站、网络、分辨率、码率和设备解码能力都会影响体验。当前记录证明部分路径可以切换，不构成同规格流畅度对比。

遇到黑屏或视频无法播放怎么办？

先区分网络与解码问题，再测试普通视频。历史媒体资源异常曾通过完整重启头显恢复；这不是应用已永久修复资源问题的保证。

这是 Wolvic 或 PICO 官方产品吗？

不是。这是社区旧设备移植，采用 legacy PicoVR，而非当前 picoxr OpenXR 后端。源码沿用 MPL-2.0，第三方组件保留各自许可。

非官方社区移植。Wolvic 及相关标识属于各自权利人。验证范围以项目记录为准，网站变化可能影响兼容性。
